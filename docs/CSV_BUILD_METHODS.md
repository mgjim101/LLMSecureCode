# CSV Build Methods and Data Lineage

This document explains how CSV outputs are built by the project scripts, with emphasis on how each transformation relates to `Tool_CSV/*` sources.

## End-to-End Build Order (Recommended)

1. `data_cleanup/filter_limesurvey.py`
2. `data_cleanup/find_complete_prolific_ids.py`
3. `tool_usage/generate_tool_usage_summary.py`
4. `code_changes_with_tool/code_changes_after_tool.py`
5. `code_changes_without_tool/code_changes_after_nudge.py`
6. `bandit_comparison_with_tool/bandit_comparison.py`
7. `bandit_comparison_without_tool/bandit_comparison_nudge.py`
8. `nudge_to_completion_duration/nudge_to_completion_durations.py`
9. `Aggregation/aggregate_nudge_metrics.py`
10. `Aggregation/generate_participant_profiles_schema.py`

The order matters because several scripts consume CSV outputs from earlier steps.

### Operational prerequisites

- The `outputs/` directory at the project root is required by steps 4–8 (they hard-code `BASE_DIR / "outputs" / "prolific_ids_with_counts.txt"` as input). It is created by step 2 (`find_complete_prolific_ids.py`). If you skip step 2 or delete `outputs/`, the downstream scripts will fail.
- `data_cleanup/find_complete_prolific_ids.py` uses a **hardcoded absolute** `BASE_DIR` path (`/Users/mgsakr/Desktop/work/Fard Lab/Analysis`). If you clone or move the repository, edit the `BASE_DIR` constant at the top of that script before running.
- Bandit (`pip install bandit`) must be on `PATH` for steps 6–7.

## 1) `data_cleanup/filter_limesurvey.py`

### Purpose
Filter LimeSurvey responses by confirmation code and extract Prolific IDs.

### Direct Inputs
- `Tool_CSV/results-survey641369.csv`

### Logic
- Reads survey CSV with pandas.
- Filters rows where:
  - column `Please paste here the confirmation code generated by the tool. ` == `761528`.
- Extracts IDs from `Unnamed: 7`.
- Prints count and IDs.

### Outputs
- Writes `outputs/filter_limesurvey_ids.csv` with one column:
  - `prolific_id`

### Relation to `Tool_CSV`
- Directly uses survey export in `Tool_CSV/results-survey641369.csv`.

## 2) `data_cleanup/find_complete_prolific_ids.py`

### Purpose
Build final participant inclusion list by requiring telemetry presence.

### Direct Inputs
- `Tool_CSV/participants.csv`
- `Tool_CSV/code_snapshots.csv`
- `Tool_CSV/tool_usage.csv`
- `outputs/complete_submissions.txt` (fallback: `complete_submissions.txt`)

### Logic
- Loads candidate Prolific IDs from complete-submissions text.
- Maps `prolific_pid -> participant_id` from `participants.csv`.
- Computes participant presence/counts in:
  - `code_snapshots.csv`
  - `tool_usage.csv`
- Keeps IDs whose participant appears in both tables.
- Detects duplicate `prolific_pid` values in `participants.csv`.

### Outputs
- Text: `outputs/prolific_ids_with_counts.txt`
- CSV: `outputs/prolific_ids_with_counts.csv` with:
  - `section` (`match` or `duplicate`)
  - `prolific_id`
  - `participant_id`
  - `code_snapshots`
  - `tool_usage`
  - `occurrences`

### Relation to `Tool_CSV`
- Directly uses participants, code snapshots, and tool usage as inclusion criteria.
- `outputs/prolific_ids_with_counts.txt` becomes the core filter for downstream scripts.

## 3) `tool_usage/generate_tool_usage_summary.py`

### Purpose
Summarize per-participant tool use vs skip decisions per task.

### Direct Inputs
- `Tool_CSV/tool_usage.csv`
- `Tool_CSV/participants.csv`
- `data_cleanup/filter_limesurvey_ids.csv`

> **Note:** Unlike the other downstream scripts (steps 4–8), `tool_usage` filters from the survey-confirmation list (`filter_limesurvey_ids.csv`), **not** the telemetry-completeness list (`outputs/prolific_ids_with_counts.txt`). The script's own top-of-file docstring is stale and still references `prolific_ids_with_counts.txt`. Participants who passed survey confirmation but lack telemetry data may therefore appear in tool-usage outputs while being filtered out elsewhere.

### Logic
- Reads candidate prolific IDs from `filter_limesurvey_ids.csv`.
- Resolves each prolific ID to an integer `participant_id` via `participants.csv`.
- Maps participant to nudge group using `participants.csv` (`group_id` 1-6 => A, 7-12 => B).
- From `tool_usage.csv`, keeps only target participants.
- For each `(participant_id, taskid)`, keeps **latest** row by `tool_decision_time`.
- Converts `tool_used` into action:
  - `true` => Used
  - `false` => Skipped
- Builds:
  - participant summary totals/percentages,
  - task interaction log with participant-local sequence order (assigned after globally sorting latest-per-task rows by timestamp),
  - global metric key/value table,
  - per-nudge per-task counts (with average tool-use rate),
  - per-nudge cross-task averaged tool-use rate.

### Outputs
- `tool_usage/tool_usage_participant_summary.csv`
- `tool_usage/tool_usage_task_interactions.csv`
- `tool_usage/tool_usage_global_metrics.csv`
- `tool_usage/tool_usage_nudge_counts.csv`
- `tool_usage/tool_usage_nudge_comparison.csv`
- Text summary: `tool_usage/tool_usage_summary.txt`

### Relation to `Tool_CSV`
- Directly depends on `tool_usage.csv` for actions and `participants.csv` for nudge labels.

## 4) `code_changes_with_tool/code_changes_after_tool.py`

### Purpose
Measure whether code changed after tool run (event 2 -> event 4).

### Direct Inputs
- `Tool_CSV/code_snapshots.csv`
- `Tool_CSV/participants.csv`
- `outputs/prolific_ids_with_counts.txt`

### Event Semantics
- Event `2`: start (`RUN_TOOL`)
- Event `4`: end (`SUB_TOOL`)

### Logic
- Keeps target participants only.
- For each `(participant_id, taskid)`:
  - selects earliest event 2 and latest event 4 (timestamp-aware fallback to row order),
  - computes `changed = start_code != end_code`,
  - computes line metrics (`start_lines`, `end_lines`, `line_delta`).
- Aggregates participant-level and nudge-task counts.

### Outputs
- `code_changes_with_tool/code_changes_after_tool_tasks.csv`
- `code_changes_with_tool/code_changes_after_tool_summary.csv`
- `code_changes_with_tool/code_changes_after_tool_nudge_counts.csv`
- Text report: `code_changes_with_tool/code_changes_after_tool.txt`

### Relation to `Tool_CSV`
- Directly driven by evented code snapshots.
- Nudge labels from `participants.csv`.

## 6) `bandit_comparison_with_tool/bandit_comparison.py`

### Purpose
Compare Bandit security findings between LLM baseline code and changed participant submissions after tool usage.

### Direct Inputs
- `Tool_CSV/code_snapshots.csv`
- `Tool_CSV/participants.csv`
- `outputs/prolific_ids_with_counts.txt`
- `LLMCode/task*.json`

### Event Scope
- Pair event `2` (start) vs event `4` (submission).
- Include only tasks where code changed between those events.

### Logic
- Runs Bandit (`bandit -f json`) on:
  - each LLM task baseline,
  - each changed participant submission (event 4 code).
- Computes per-task and per-submission:
  - issue totals,
  - severity totals,
  - type deltas (`new`, `fixed`, `common`),
  - severity diffs versus baseline.
- Aggregates by nudge/task and by nudge overall.

### Outputs
- `bandit_comparison_with_tool/bandit_comparison_llm_tasks.csv`
- `bandit_comparison_with_tool/bandit_comparison_participant_submissions.csv`
- `bandit_comparison_with_tool/bandit_comparison_type_changes.csv`
- `bandit_comparison_with_tool/bandit_comparison_nudge_counts.csv`
- `bandit_comparison_with_tool/bandit_comparison_nudge_task_total_diffs.csv`
- `bandit_comparison_with_tool/bandit_comparison_nudge_total_diffs.csv`
- Text report: `bandit_comparison_with_tool/bandit_comparison.txt`

### Relation to `Tool_CSV`
- Uses snapshots for participant code and participants for nudge mapping.
- Security results combine Tool_CSV-derived participant code with LLM baselines.

## 8) `nudge_to_completion_duration/nudge_to_completion_durations.py`

### Purpose
Compute elapsed time from nudge to completion for participant-task pairs.

### Direct Inputs
- `Tool_CSV/code_snapshots.csv`
- `Tool_CSV/participants.csv`
- `outputs/prolific_ids_with_counts.txt`

### Event Semantics
- Nudge: event `1`
- Completion: event `3` or `4`

### Logic
- For each `(participant_id, taskid)`:
  - choose earliest nudge timestamp,
  - choose earliest completion timestamp at/after that nudge,
  - compute duration seconds and hh:mm:ss format.
- Produces matched duration rows and averages by task x nudge.

### Outputs
- `nudge_to_completion_duration/nudge_to_completion_durations.csv`
  - written as sibling of `outputs/nudge_to_completion_durations.txt`
- `nudge_to_completion_duration/nudge_to_completion_avg_by_task_nudge.csv`
- Text report: `outputs/nudge_to_completion_durations.txt`

### Relation to `Tool_CSV`
- Directly uses code snapshot timestamps/events and participant grouping.

## 9) `aggregate_nudge_metrics.py`

### Purpose
Create one wide summary table with two rows (nudge A/B) and task-wise metrics.

### Direct Inputs
- Derived CSVs from previous scripts:
  - `tool_usage/tool_usage_nudge_counts.csv`
  - `code_changes_with_tool/code_changes_after_tool_nudge_counts.csv`
  - `code_changes_without_tool/code_changes_after_nudge_nudge_counts.csv`
  - `bandit_comparison_with_tool/bandit_comparison_nudge_counts.csv`
  - `bandit_comparison_without_tool/bandit_comparison_nudge_nudge_counts.csv`
  - `bandit_comparison_with_tool/bandit_comparison_nudge_task_total_diffs.csv`
  - `bandit_comparison_without_tool/bandit_comparison_nudge_nudge_task_total_diffs.csv`
  - `nudge_to_completion_duration/nudge_to_completion_avg_by_task_nudge.csv`

### Logic
- Indexes each source by `(nudge, task_id/taskid)`.
- For nudge in `{A,B}` and task in `{1,2,3}`, copies mapped values into fixed wide columns.
- Missing metrics default to `"0"` (duration defaults to empty string).

### Outputs
- `nudge_aggregated_summary.csv`

### Relation to `Tool_CSV`
- Indirect only: entirely derived from upstream CSVs that originate from Tool_CSV sources.

## 10) `Aggregation/generate_participant_profiles_schema.py`

### Purpose
Build one very wide participant profile table combining behavior, security, timing, and survey data.

### Direct Inputs
- `data_cleanup/prolific_ids_with_counts.csv`
- `tool_usage/tool_usage_participant_summary.csv`
- `tool_usage/tool_usage_task_interactions.csv`
- `code_changes_with_tool/code_changes_after_tool_tasks.csv`
- `code_changes_without_tool/code_changes_after_nudge_tasks.csv`
- `nudge_to_completion_duration/nudge_to_completion_durations.csv`
- `bandit_comparison_with_tool/bandit_comparison_participant_submissions.csv`
- `bandit_comparison_without_tool/bandit_comparison_nudge_participant_submissions.csv`
- `bandit_comparison_with_tool/bandit_comparison_type_changes.csv`
- `bandit_comparison_without_tool/bandit_comparison_nudge_type_changes.csv`
- `Aggregation/results-survey641369.csv`

### Logic
- Iterates participant rows from inclusion list.
- For each task 1/2/3:
  - determines tool-use boolean from interaction action,
  - selects task metrics from with-tool or without-tool tables accordingly,
  - fills changed/line fields, bandit counts/diffs/types,
  - fills completion duration (hh:mm:ss) only for tool-used branch.
- Appends full survey row by Prolific ID; when a Prolific ID has multiple matching survey rows, keeps the row with the **most non-empty fields** (not the first match).
- Handles duplicate/blank survey headers by unique renaming.

### Outputs
- `Aggregation/participant_profiles_schema.csv`

> The script's top-of-file docstring still claims output is `data_cleanup/participant_profiles_schema.csv`; that comment is stale. The actual `OUTPUT_CSV` constant writes to `Aggregation/`.

### Relation to `Tool_CSV`
- Primarily indirect (through upstream derived tables),
- plus direct survey relation through `Aggregation/results-survey641369.csv` (not `Tool_CSV/results-survey641369.csv` in this script).

## Key Cross-Script Dependencies

- `outputs/prolific_ids_with_counts.txt` is the participant filter backbone for most analysis scripts.
- Event semantics in `Tool_CSV/code_snapshots.csv` drive:
  - change detection (`1->3`, `2->4`),
  - nudge-to-completion timing (`1->3/4`),
  - participant submission selection for Bandit.
- `Tool_CSV/participants.csv` provides nudge-group assignment used throughout (`A` vs `B`).

## Operational Notes

- Some folder outputs may include legacy/alternate filenames from earlier runs.
- Several scripts write both text and CSV outputs; CSVs are the canonical machine-readable artifacts.
- If reproducing from scratch, run scripts in the recommended order and verify path assumptions (`outputs/` vs local-folder copies).
- **Filename inconsistency between `bandit_comparison_nudge.py` and `aggregate_nudge_metrics.py`:** the without-tool Bandit script writes `bandit_comparison_without_tool/bandit_comparison_nudge_task_total_diffs.csv`, but the aggregator reads `bandit_comparison_without_tool/bandit_comparison_nudge_nudge_task_total_diffs.csv` (the legacy on-disk name). After re-running the without-tool Bandit script, the aggregator will silently keep using the stale legacy file unless the new file is renamed to match.
